1. Job posting

Submitting a posting extracts structured requirements with the backend LLM. The API has no listing endpoint, so this page keeps the returned posting ID.

Use an existing posting ID

2. Repository

Indexing fetches the repository, chunks it, and stores embeddings. Re-running is safe: the backend is idempotent and skips work when the commit is unchanged.

3. Assess requirements

Runs evidence retrieval for every requirement, then asks the backend model for a verdict per requirement. Repeating this for the same commit returns the stored assessment instead of re-running the model.

Save a job posting and index a repository first.

Assessment results

How to read the statuses

  • ✓ Supported the retrieved code clearly demonstrates the requirement.
  • ◐ Partial the retrieved code demonstrates only part of the requirement.
  • ✕ Not found not demonstrated in the analyzed repository — this is not proof that a candidate lacks the skill.

The browser never decides these statuses. They are shown exactly as the backend assessment returned them.
